# V3 evaluation and release

[The detailed Chinese evaluation report](DETAILED_EVALUATION_REPORT.md) consolidates the measured runs, question completeness, latency/token statistics, functional regressions and outstanding quality gates. On 2026-09-28 parser/pipeline 5 was deployed to local Docker, all 46 V3 indexes were rebuilt, and the real model service completed both source-backed and eight-format evaluations. [Supplementary statistics](detailed_report_metrics.json) cover the historical runs; the current summaries are [pipeline 5 boundary observations](local_context5_observations.json) and [source comparison](business/comparison-v5.json).

The calibrated V3 mode is not release-ready. The operational rules mode is documented in `docs/RAG_V3_OPERATIONS.md` and does not claim calibrated quality. `cases.jsonl` contains 192 **synthetic boundary cases**, not independently reviewed labels. The calibration domains (inventory, education, facilities) and locked validation domains (publishing, events, software) have no overlap. Every domain contains all eight formats, including PDF, PPTX and XLSX. `python scripts/build_v3_binary_fixtures.py` regenerates the 18 binary fixtures and their 72 cases. Automated tests check that annotated facts and locations survive parsing; they do not establish retrieval quality. Human review, diverse long documents, comparison questions, scanned PDF cases and additional permission fixtures remain necessary. Do not change `review_status` merely because automated tests pass.

## Run

### Source-pinned development questions

[The first source-backed question set](business/questions.md) contains four maintained project-document snapshots and the public NIST IR 8397 PDF: 24 answerable questions and five no-answer questions. These are authentic project/public sources, not customer documents. Labels remain `agent_draft` and this is a development corpus; it does not replace locked validation or independent review. Snapshots and JSONL labels retain their measured bytes through Git attributes. `business/sources.json` records checksums, source URLs and the repository revision.

Run `pwsh -File scripts/record_local_v3_business.ps1 -OutputDirectory data/evaluations/business-run` against the current Docker deployment. `-UseWorkspaceBackend` evaluates a separate child-process code copy before deployment; the isolated parser imports that same copy. Complete reports require SQL rollback and verified cleanup of the generated search IDs. The evaluator checks document hashes before indexing, measures all five documents in the same tenant, and credits PDF facts only at the annotated physical page. Whitespace is normalized for matching while values, negation and original citation text remain intact. `scripts/summarize_v3_business_comparison.py` rejects incomplete/invalid runs, changed documents, labels, models or budgets. [Measured results](business/RESULTS.md) distinguish development observations from release approval.

### Operational observations on local Docker

`powershell -File scripts/record_local_v3_evaluation.ps1` records 40 authored XL-107 demo questions and the 192 synthetic boundary questions at budget 1200. Use `-Dataset Demo` or `-Dataset Boundary` for a subset; in a PowerShell session pass `-Budgets @(600,1200,1800)` to measure all budgets. Services must already be ready. Raw reports are saved under ignored `data/evaluations/<run-id>` and contain the selected evidence, candidate diagnostics, exact-source coverage, citation checks and warm latency. Demo SQL is read-only. Each synthetic format uses an uncommitted tenant, rolls back its SQL and deletes only its generated OpenSearch source IDs, then verifies cleanup. Parsing/indexing time is separate from warm query time. Run evaluations sequentially on the same model service to keep latency measurements comparable.

These observations do not train a classifier, claim independent review, measure an older baseline, or authorize calibrated mode. Short fact values use token boundaries and annotated source keys; protected conditions and exact source metadata/text must survive. This deterministic scoring still needs reviewer confirmation, especially for negative answers and semantic completeness.

The local measurements from 2026-09-27 are recorded in `local_demo_observations.json` (120 runs at three budgets) and `local_boundary_observations.json` (192 runs, eight formats). At budget 1200 the demo's 54 necessary source spans survived, but the synthetic corpus's final selected span coverage was only 21.1%, despite candidate recall of 99.4%. All eight formats were below the 90% selected-coverage target. Citation, scope and budget checks found zero violations in these runs, not a universal permission guarantee. The current heuristic threshold/model pair must not be represented as quality-approved. One demo no-answer annotation returned an explicit source statement that real keys are not provided; it needs reviewer assessment. See [the independent review checklist](REVIEW_CHECKLIST.md).

These earlier observations used parser/pipeline 3. After the source-context and PDF changes, [parser/pipeline 4 observations](local_context_observations.json) cover the same 192 labels: selected coverage improves to 62.3%, with zero observed no-answer, citation, scope or budget violations. Only TXT reaches 90%; quality gates remain unmet. The code was frozen before this full run, and validation-domain results were not used for another code adjustment. Source-backed development observations are reported separately in [business/RESULTS.md](business/RESULTS.md); PDF there still achieves only 62.5% selected coverage.

[Parser/pipeline 5 observations](local_context5_observations.json) cover the same 192 labels after deployment and reindexing. Candidate recall and selected coverage are 318/318 (100%); every format, including PDF and XLSX, reaches 100%. All 48 no-answer cases return no evidence, with zero observed citation, scope or budget violations. The 29 source-backed questions also reach 44/44 selected spans, including PDF 8/8. These results pass local automated technical gates, while independent review, representative customer documents, paired pipeline 5 model comparison and generated-answer scoring remain required for formal quality approval.

The optional `docker-compose.v3-evaluation.yml` adds an isolated model service, with no host port, a 5 GiB memory cap, read-only model cache and pinned settings in `config/retrieval.v3-multilingual.env.example`. It is not enabled by the normal local deployment. Download the candidate weights explicitly with `model-download` and matching environment overrides before starting it. The download script verifies the weight commit, prefers safetensors and supports the pinned BGE-M3 PyTorch BIN weights; missing weights stop setup. The candidate revisions were checked against the official [BGE-M3 revision](https://huggingface.co/BAAI/bge-m3/tree/5617a9f61b028005a4858fdac845db406aefb181) and [reranker revision](https://huggingface.co/BAAI/bge-reranker-v2-m3/tree/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e).

Start the candidate with `docker compose -f docker-compose.yml -f docker-compose.v3-evaluation.yml --profile v3-evaluation up -d --no-deps retrieval-evaluation`, wait for `/health/ready`, then run `./scripts/record_local_v3_evaluation.ps1 -Dataset Boundary -ModelProfile config/rag.v3.multilingual.example.json`. Only the evaluation subprocess receives the profile; deployed API/chat/Agent settings remain their configured values. On limited-memory hosts, evaluate sequentially and restore the operational retrieval service before business checks. Operational observations still do not replace calibrated paired baseline/locked validation.

`./scripts/compare_local_v3_models.ps1` automates sequential measurements, candidate readiness and restoration of the configured model service in a `finally` block, including when candidate warmup/evaluation fails. Reports go to `data/evaluations/paired-<run-id>`; no model is automatically selected. `-CurrentReport <raw-boundary-report>` reuses complete observations on the exact corpus and `-SkipDownload` uses already prepared weights. Both models must be measured on the same host; formal acceptance also requires independently reviewed labels and paired older baselines. The candidate may fail its resource cap; record that result without increasing the local engine's memory or changing the active model silently.

The candidate's actual 192 observations are summarized in `local_model_comparison.json`: selected span coverage was 30.8%, with only JSON reaching 90%; warm P95 was 14,007 ms versus the current model's 2,931 ms. Neither profile passed overall quality acceptance. The operational model was restored and the optional candidate container removed; weights remain cached. See [local acceptance and remaining work](LOCAL_ACCEPTANCE.md).

### Formal calibrated acceptance

1. Apply migrations through the repository head; set `RAG_V3_INDEXING_ENABLED=true` in a staging environment. Upload files via `/api/knowledge/files`, or enqueue existing text via `POST /api/knowledge/{id}/v3-index`. PDF/PPTX/XLSX require their saved originals. Keep the operational relevance mode at `rules` until calibrated validation is approved.
2. Compare the current BGE pair against `BAAI/bge-m3` / `BAAI/bge-reranker-v2-m3` in a **separate model service**. The multilingual model is a candidate, not a selected winner. Set `RAG_V3_MODEL_PROFILE` to a JSON settings file; it overrides only V3 embedding/reranker settings. Pin model revisions to 40-character weight commits. Do not use `main` in a release. V3 vectors support 512 and 1024 dimensions and authorize/filter identity before distance evaluation.
3. Record candidate features and independently reviewed relevant/irrelevant labels as JSONL: `split`, `relevant`, `features` (rerank, gap, identifier, query_terms, heading_terms, structured, phrase, condition_terms). Run `python scripts/evaluate_rag_v3.py calibrate --runs calibration-features.jsonl --output classifier.json`. Only calibration rows are accepted. Freeze classifier and manifest hashes before validation.
4. Record paired runs with fields `id`, `format`, `kind`, `necessary_total`, `recalled_necessary`, `covered_necessary`, `old_covered_necessary`, `old_tokens`, `final_tokens`, `budget`, `returned_relevant`, `permission_leaks`, `source_mismatches`, `fact_corruptions`, `warm_latency_ms`, `old_warm_latency_ms`. For PDF/PPTX/XLSX, use the same content in an authorized MD/TXT reference as the `old_*` comparator; do not describe this as an older binary parser. Both runs must use the same machine, model profile, question and permission scope. Necessary-fact matching requires verified source positions, values and protected conditions, not substring-only keyword checks. Cold starts, parsing and indexing durations are recorded separately.
5. Run `python scripts/evaluate_rag_v3.py validate --cases evaluations/v3/cases.jsonl --runs locked-runs.jsonl --output report.json`. Failed gates remain failures; validation must not be used to tune parameters. Pair the model profiles by Chinese/English macro recall, completeness, and warm latency. Equivalent results favor the current pair.
6. Independently review the report. The release report must contain checked metrics for all eight formats, model comparison and reviewer approval, `identity` and SHA256 of canonical classifier JSON. A release file contains `identity`, `classifier`, `report`, and `report_sha256`. Only then set `RAG_V3_RELEVANCE_MODE=calibrated`; the API checks the release before retrieval. Keep chat and Agent on the operational V3 rules mode until this approval.

## Current limitations / release blockers

- Synthetic corpus is not independently reviewed and is not sufficiently diverse for release.
- Two real model services have been measured on local synthetic observations. Independently reviewed calibration, paired older baselines, locked validation and formal latency acceptance are pending.
- Long indivisible atoms are split only for indexing; they are reassembled only when all required parts pass relevance filtering and fit the budget. Otherwise they are omitted with an explicit diagnostic.
- Exact body duplicates are deduplicated within a source; cross-source near-duplicate merging is deliberately conservative. JSON path conflicts are flagged as potential conflicts, not resolved answers.
- Query evidence uses the retrieval tokenizer; future generation tokenizer and full request budgets are outside this release.

Model references: [BGE-M3](https://huggingface.co/BAAI/bge-m3), [BGE reranker v2 M3](https://huggingface.co/BAAI/bge-reranker-v2-m3). Review the exact pinned revisions used by the model service, not only these mutable landing pages.

Rollback of the calibrated classifier: set `RAG_V3_RELEVANCE_MODE=rules`. Pause indexing separately with `RAG_V3_INDEXING_ENABLED=false`. Preserve failed reports and side-index data for diagnosis. Knowledge PDF, PPTX and XLSX remain on V3; unsupported DOC/PPT/XLS require conversion.
