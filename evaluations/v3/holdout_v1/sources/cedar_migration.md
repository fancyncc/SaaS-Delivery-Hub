# Cedar 实验设备公司数据迁移规则

## 标识与字段转换

旧系统的 `user_id` 写入新系统的 `external_ref`。转换时移除首尾空格，但必须保留前导零，例如 ` 00127 ` 应写为 `00127`。`dept_code` 通过冻结的部门映射表转换；找不到映射时不得自动创建部门。

所有时间先按源系统时区解析，再转换为 UTC 的 ISO 8601 格式。形如 `03/04/25` 的歧义日期必须以错误码 `M-214` 拒绝，不能猜测月日顺序。空手机号保持为空，不得使用 `00000000000` 补位。

## 重复记录

人员重复键为规范化邮箱与 `tenant_code` 的组合。只有当重复记录全部为 active 状态时，才保留 `updated_at` 最新的一条；只要其中存在 suspended 或 terminated 状态，整组记录进入人工复核。邮箱大小写差异不产生新人员。

设备记录使用 `serial_number` 作为唯一键。序列号相同但设备型号不同属于冲突，不能覆盖旧记录。

## 批次门槛

迁移分为预检、试导入和正式导入三遍。正式导入前，试导入拒绝行比例必须不超过 0.8%，并且拒绝行绝对数量必须不超过 25；两个条件需要同时满足。即使比例很低，只要拒绝行达到 26 条也不能继续。

附件和历史评论不在本期迁移范围内。每一遍都要保存输入文件 SHA-256、映射表版本、成功数量、拒绝数量和逐行错误文件。原始 CSV 保存 90 天，逐行错误文件保存 180 天。

## 回退

正式导入失败时，只删除本批次创建且尚未被业务修改的记录。已经被用户编辑的记录转入补偿清单，不允许直接回滚覆盖。
